# 🧠 CodeMaster AI

### AI-powered coding-interview practice — generate, verify and solve LeetCode-style problems

An **admin panel (React + Vite)** and an **Express API** backed by **MongoDB**. It generates
LeetCode / Codeforces-style coding problems and MCQs with up to **18 AI providers and automatic
fallback**, verifies every generated test case by executing the reference solution, and gives you a
LeetCode-like solver with hints, AI reviews, attempt history and daily automation.

## Features

| Area | What you get |
|---|---|
| **Question generation** | Coding problems (statement, I/O format, constraints, examples, hidden tests, 3 progressive hints, editorial, complexity, starter + reference solution, follow-ups) and MCQs. Difficulty **Easy / Medium / Hard / Very Hard**, 13 programming languages (+ SQL and language-agnostic DSA/CS for MCQs), 35+ topics or a custom topic. |
| **Prompt templates** | 12 built-in, editable templates (one per difficulty for coding and MCQ, plus Google-interview style, real-world systems, predict-the-output, DSA & complexity). Variables `{{difficulty}}`, `{{language}}`, `{{topic}}`, `{{count}}`, `{{extra}}`. The strict JSON output contract is appended automatically, so templates can never break parsing. |
| **18 AI providers + fallback** | Gemini, Groq, Cerebras, OpenRouter, Mistral, SambaNova, NVIDIA NIM, Cohere, Hugging Face, Z.ai (GLM), SiliconFlow, Together, Cloudflare Workers AI, DeepSeek, OpenAI, Anthropic Claude, Ollama (local) and any OpenAI-compatible API. Priority or round-robin routing; a failing, rate-limited or invalid-key provider is skipped automatically (with cooldowns). Per-provider model, token limit, enable toggle, **Test** / **Test all** with a saved status board (working, no credits, invalid key, disabled, no key) and live model list. |
| **Verified test cases** | For every generated coding problem the reference solution is run on all tests. Wrong expected outputs are auto-corrected; problems whose solution doesn't compile or disagrees with most tests are regenerated by the next provider. Duplicate titles are rejected. |
| **LeetCode-style solver** | Monaco editor, language switch with AI starter-code translation, **Run** (examples or custom input - the expected output comes from the reference solution), **Submit** (hidden tests, stops at first failure), verdicts AC / WA / TLE / RE / CE with per-test diff, draft autosave, timer, `Ctrl+Enter` / `Ctrl+Shift+Enter`. |
| **Hints & AI help** | Progressive stored hints, AI hints that read *your* code without giving away the solution, AI interview review (Strong Hire ... No Hire, code quality, complexity, improvements), editorial / solution reveal. |
| **Attempts & reattempts** | Every submission and MCQ answer is stored in MongoDB. **Reattempt** resets status, hints and solution access so you can solve it fresh - history is kept. Reattempt queue and "due for revision" lists on the dashboard. |
| **Daily automation** | Schedules such as "every day 09:00 -> 1 easy + 2 medium + 1 hard coding + 5 MCQs". Weekday selection or a custom cron, run-now, history with live logs, and catch-up if the PC was off at the scheduled time. |
| **AI usage analytics** | Calls, success rate, tokens, latency, requests rescued by fallback, usage per provider / purpose / day, a full request log - plus your own AI dependence (hints, AI hints, reviews, solution views, independent-solve rate). |
| **Code runners** | Local runtimes (Node.js always; Python, g++, gcc, Java, Go, Rust, PHP, Ruby when installed) -> **Wandbox** (free online compilers, no key) -> Judge0 -> self-hosted Piston -> AI judge as a last resort (marked approximate). |

## Quick start

Requirements: **Node.js 22.12+** and an internet connection (AI APIs, Monaco editor CDN, online compilers).

```bash
npm run install:all          # installs root, backend and frontend dependencies
```

1. Fill the backend env files (see below): `ADMIN_EMAIL` and AI keys in `backend/.env`,
   the admin password in `backend/.env.development` / `backend/.env.production`.
2. Start everything:

```bash
npm run dev                  # API on :5050 + Vite admin panel on :5173
```

3. Open **http://localhost:5173** and sign in with the admin email + password.

> With `MONGODB_URI` empty, the first start downloads a MongoDB server binary once (300-600 MB)
> for the built-in database. Sample questions, all prompt templates and a (disabled) daily
> schedule are created automatically, so you can try the solver before adding any API key.

Added or changed a key later? Click **Reload .env** on the *AI Providers* page - no restart needed.

## Environment files

Both apps use the same convention (later files override earlier ones):
`.env` -> `.env.local` -> `.env.<mode>` -> `.env.<mode>.local`
(`npm run dev` = development, `npm start` = production; real OS environment variables always win).

| File | Purpose | Commit? |
|---|---|---|
| `backend/.env` | Shared by both modes: `ADMIN_EMAIL`, MongoDB Atlas URI, all AI keys, code-runner keys. | **No** |
| `backend/.env.development` | Dev: `127.0.0.1:5050`, Vite CORS origin, database `codemaster_dev`, plain dev password, dev JWT secret (7 d), request logs on. | **No** |
| `backend/.env.production` | Prod: `0.0.0.0:5050`, database `codemaster`, **scrypt password hash**, own JWT secret (12 h), logs off, `TRUST_PROXY`. | **No** |
| `backend/.env.example` | Documented template of every variable. | Yes |
| `frontend/.env` | Shared UI settings (`VITE_APP_NAME`, `VITE_API_URL`). | Yes |
| `frontend/.env.development` | Dev API base + `DEV_API_PROXY` (Vite proxy target, not exposed to the browser). | Yes |
| `frontend/.env.production` | API base for the production build. | Yes |
| `frontend/.env.example` | Documented template. | Yes |

Only `VITE_*` variables reach the browser - secrets live only in the backend files.

**Admin login.** `ADMIN_EMAIL` + `ADMIN_PASSWORD` (plain, fine for local development) or
`ADMIN_PASSWORD_HASH` (recommended for production). Create a hash with:

```bash
npm --prefix backend run hash-password -- "YourNewPassword"
```

and paste the printed `ADMIN_PASSWORD_HASH='scrypt$...'` line into `backend/.env.production`.
Logins are rate limited (10 failures per IP / 15 min) and sessions are JWTs signed per mode.

### Provider status

**Test all** on the *AI Providers* page sends one tiny request to every provider that has a key and
stores the result in MongoDB. The page then shows, also after a restart, which providers are
**Working**, **Not working** (No credits, Invalid key, Paid plan needed, Model not found, Busy / rate
limited), **Disabled** or have **No key**, with a hint for each failure. A result is marked stale when
the key or the model list changes. Disabled providers are skipped by the fallback; switch them back on
after topping up. The backend start-up log lists failing and disabled providers as well.

### How fallback works

Each request walks every (provider, model) pair in your priority order (or round-robin). A pair is
skipped when it errors, times out, returns invalid JSON, an answer that does not match the schema, or
a question that fails verification; the next one is tried immediately. Overloaded / rate-limited /
no-balance / paid-plan-only / removed models cool down individually (respecting `Retry-After`), so
the provider's free models keep working; an invalid key cools the whole provider down for 10 minutes. Every attempt is logged, so the *AI Usage* page shows exactly
which model answered and how many requests were rescued by fallback.

## Prompt library (`backend/prompts/`)

Every prompt sent to an AI lives in files - generation templates (6 coding + 6 MCQ), system
personas, output contracts, assistant prompts (hints, reviews, judge, starter code) and JSON
Schemas. See [`backend/prompts/README.md`](backend/prompts/README.md).

- Each AI answer is **normalized** (aliases, markdown fences, letter answers, `A)` prefixes...) and
  **validated** against `schemas/coding-question.schema.json` / `mcq-question.schema.json` before it
  is stored - a non-conforming answer is rejected and the next provider is asked. Every question is
  saved with `schemaVersion` and `generation` metadata (provider, model, prompt key + version,
  tokens, latency); raw answers are kept in `airesponses` for 90 days.
- Files sync to MongoDB on start (dev restarts on file changes) or with **Sync from folder** on the
  *Prompt Templates* page. Edits made in the panel are kept until you **Reset**.
- **Test** on a template dry-runs it against your providers and shows the validated result, the
  stored JSON and the raw answer - without saving anything.
- `npm --prefix backend test` checks the library, the contracts and the normalizer against clean
  and messy example answers in `prompts/examples/`.

## MongoDB

- **Default:** `MONGODB_URI` empty -> a built-in MongoDB runs inside the backend and stores data in
  `backend/data/mongo`. Nothing to install.
- **MongoDB Atlas (current setup):** `MONGODB_URI=mongodb+srv://...` in `backend/.env`; development
  uses the `codemaster_dev` database and production `codemaster`, so test data never mixes with
  real data. In Atlas, *Network Access* must allow your IP (or the server's IP in production).
- **Your own server:** e.g. `MONGODB_URI=mongodb://127.0.0.1:27017`.
- Some Windows setups hand Node a DNS server that refuses the SRV lookups `mongodb+srv` needs
  (`querySrv ECONNREFUSED`); the backend then retries with public DNS automatically
  (force servers with `DNS_SERVERS=1.1.1.1,8.8.8.8`).

**Older CPUs:** MongoDB 5.0+ requires a CPU with AVX. The backend detects this; on CPUs without
AVX (for example Intel Celeron / Pentium Silver) the built-in database automatically uses
MongoDB 4.4, the newest version that runs there. If you install MongoDB yourself on such a machine,
install 4.4 or use MongoDB Atlas.

Collections: `questions` (with embedded progress, `schemaVersion`, `generation`), `submissions`
(every attempt), `prompts`, `schedules`, `jobs`, `ailogs` (every provider attempt), `airesponses`
(raw AI answers, 90-day TTL), `settings`, `counters`.

## Code execution

Runners are tried in the order set on the *Settings* page:

1. **Local** - Node.js (JavaScript / TypeScript) always; Python, C/C++, Java, Go, Rust, PHP, Ruby when
   installed (click *Re-detect* after installing). Fastest and unlimited.
2. **Wandbox** - free online compilers, no key (C++, Java, Python, Go, Rust, C#, PHP, Ruby, Swift, ...).
3. **Judge0** - RapidAPI key or your own server (`JUDGE0_URL`, `JUDGE0_API_KEY`).
4. **Piston** - self-hosted only (`PISTON_URL`); the public Piston API is whitelist-only.
5. **AI judge** - only when nothing else can run the language; results are marked *approximate*.

When a generated problem's language cannot run locally, the AI also writes an independent Node.js
reference so tests can still be verified on your machine.

> Code you submit runs on the backend machine. Keep `HOST=127.0.0.1` unless the server is protected
> (it is admin-only behind a password and JWT).

## Production

```bash
npm run install:all   # once
npm run build         # builds frontend/dist
npm start             # backend in production mode, serves the UI and API on http://localhost:5050
```

`backend/.env.production` is ready for a server: binds `0.0.0.0:5050`, uses the `codemaster`
database, a scrypt `ADMIN_PASSWORD_HASH`, its own `JWT_SECRET` (12 h sessions), no request logs,
gzip compression, security headers and long-lived caching for hashed assets. Before deploying:

- copy `backend/.env` and `backend/.env.production` to the server (they are git-ignored - never
  commit them);
- set `CLIENT_ORIGIN` to your public URL and, behind Nginx / Render / Railway, `TRUST_PROXY=1`;
- allow the server's IP in MongoDB Atlas *Network Access*;
- open *AI Providers* → **Test all** once: production has its own database, so provider
  enable/disable choices and test results are separate from development;
- keep it running with a process manager (pm2, systemd, or NSSM on Windows) and point an uptime
  monitor at `GET /api/health`;
- on Windows, binding `0.0.0.0` makes the firewall ask once whether Node may accept connections
  (use `HOST=127.0.0.1` to keep it local).

If the frontend is hosted separately, set `VITE_API_URL` (frontend `.env.production`) to the backend
URL and add that origin to `CLIENT_ORIGIN`.

### Deploy

**Render (one click):** press **Deploy to Render** at the top. `render.yaml` builds the admin panel,
starts the API in production mode and generates `JWT_SECRET`. Fill in the dashboard:

| Variable | Value |
|---|---|
| `MONGODB_URI` | Atlas connection string (required - the built-in database is for local use) |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD_HASH` | Your login (`npm --prefix backend run hash-password -- "pw"`) |
| `CLIENT_ORIGIN` | Your Render URL, e.g. `https://codemaster-ai.onrender.com` |
| `GEMINI_API_KEY`, `GROQ_API_KEY`, ... | Any AI provider keys you want to use |

Allow `0.0.0.0/0` in Atlas *Network Access*. On Render only Node.js runs locally - other languages
use Wandbox automatically. Free instances sleep when idle; daily schedules catch up when they wake.

## Troubleshooting

- **"No AI provider is configured"** - add a key to `backend/.env`, then *Reload .env* on the *AI Providers* page and press **Test**.
- **A provider shows "Cooling down"** - it was rate-limited or its key is invalid; the others keep working. It is retried automatically.
- **"No credits"** - the account behind that key has no balance (SambaNova, DeepSeek, OpenAI, Anthropic; SiliconFlow also blocks its free models once the balance goes negative). Top up on the provider's website and press **Test**, or leave it disabled.
- **Model not found** - free-tier catalogs change; open *AI Providers*, click **Models** and pick another model.
- **Editor doesn't load** - Monaco is loaded from the jsDelivr CDN; check your internet connection.
- **Slow Run/Submit for Python/C++/Java** - those run on Wandbox until you install the compiler locally.
- **Port already in use** - change `PORT` in `backend/.env.development` (and `DEV_API_PROXY` in `frontend/.env.development`).
